# v0.4.0 — Production Crash Fixes

**Release Date:** 2026-09-03

This release fixes critical production crashes on Android 14+ and iOS 17/18, addresses memory and disk leaks, and improves cross-platform consistency.

---

## 🔴 Critical Fixes (Fatal Crashes)

### Android 14+ `MissingForegroundServiceTypeException`
- **File:** `android/src/main/java/com/transferkit/upload/UploadWorker.kt`
- **Fix:** Changed `createForegroundInfo()` from 2-argument `ForegroundInfo(id, notification)` to 3-argument `ForegroundInfo(id, notification, FOREGROUND_SERVICE_TYPE_DATA_SYNC)` on API 29+.
- **File:** `android/src/main/AndroidManifest.xml`
- **Fix:** Added `FOREGROUND_SERVICE_DATA_SYNC` and `POST_NOTIFICATIONS` permissions, plus `<service android:foregroundServiceType="dataSync">` declaration for WorkManager's `SystemForegroundService`. These are auto-merged into the host app via Android's manifest merger — **no host app changes needed**.

### Android 12+ `ForegroundServiceStartNotAllowedException`
- **File:** `android/src/main/java/com/transferkit/upload/UploadWorker.kt`
- **Fix:** Wrapped `setForegroundAsync()` in try/catch. If foreground promotion fails (app is in background), the upload continues as a background worker instead of crashing.

### Android 14+ `SecurityException` on `registerReceiver()`
- **File:** `android/src/main/java/com/transferkit/upload/UploadManager.kt`
- **Fix:** Replaced `context.registerReceiver(receiver, filter)` with `ContextCompat.registerReceiver(context, receiver, filter, ContextCompat.RECEIVER_NOT_EXPORTED)`. Backward compatible via AndroidX Core.

## 🟠 Crash Fixes

### React Native Lifecycle Crash on Android
- **File:** `android/src/main/java/com/transferkit/TransferkitModule.kt`
- **Fix:** Added `context.hasActiveCatalystInstance()` guard and `try/catch` for `IllegalStateException` around all `sendEvent()` calls. Events emitted after bridge teardown are now silently dropped instead of crashing.
- **Fix:** Added `invalidate()` override to clean up the `UploadManager` broadcast receiver when the React Native module is destroyed, preventing context leaks.

---

## 🟠 iOS OOM / Jetsam Fix

### In-Memory File Loading Replaced with Streamed I/O
- **File:** `ios/upload/TKUploadManager.mm`
- **Before:** `[NSData dataWithContentsOfURL:]` loaded the entire file into RAM, then `[NSMutableData appendData:]` duplicated it. Peak memory ≈ 3× file size. A 500MB video consumed ~1.5GB of RAM, triggering iOS Jetsam termination.
- **After:** New `writeMultipartBodyToFile:` method uses `NSInputStream` + `NSOutputStream` to stream file contents in 256KB chunks directly to the temp file. Peak memory is now ~256KB regardless of file size.

---

## 🟡 iOS Background Session Lifecycle

### Background Upload Completion Support
- **File:** `ios/upload/TKUploadManager.h`
- **New:** Added `+ (void)handleBackgroundSessionCompletionHandler:(void (^)(void))completionHandler` class method.
- **File:** `ios/upload/TKUploadManager.mm`
- **New:** Implemented `URLSessionDidFinishEventsForBackgroundURLSession:` delegate method. When all background events are delivered, the stored completion handler is invoked on the main thread.
- **Note:** Host apps must call this from their `AppDelegate`:
  ```objc
  - (void)application:(UIApplication *)application
      handleEventsForBackgroundURLSession:(NSString *)identifier
      completionHandler:(void (^)(void))completionHandler {
      if ([identifier isEqualToString:@"com.transferkit.upload"]) {
          [TKUploadManager handleBackgroundSessionCompletionHandler:completionHandler];
      }
  }
  ```

## 🟡 Disk Leak Fixes

### Android: Temp File Cleanup
- **File:** `android/src/main/java/com/transferkit/upload/UploadWorker.kt`
- **Fix:** Added `cleanupTempFile()` in `finally` block after upload completes (success, failure, or exception). Temp files created from `content://` URIs in `cacheDir` are now always deleted.

### iOS: Temp File Cleanup
- **File:** `ios/upload/TKUploadManager.mm`
- **Fix:** Added `tempFilesMap` to track temp file URLs. `cleanupTempFile:` is called in `didCompleteWithError:` and `cancelUpload:`. `cleanupAllTempFiles` is called when cancelling all uploads.

## 🔵 Cross-Platform Consistency

### Event Emitter Platform Handling
- **File:** `src/eventEmitter.ts`
- **Fix:** Uses `Platform.OS` to pass `NativeModules.TransferkitEventEmitter` on iOS and `undefined` on Android. Makes implicit behavior explicit and forward-compatible with TurboModules.

### `statusCode` in Android Error Events
- **Files:** `UploadWorker.kt`, `UploadManager.kt`, `TransferkitModule.kt`
- **Fix:** Android `onUploadError` events now include `statusCode` (integer) when an HTTP error occurs, matching the existing iOS behavior.
